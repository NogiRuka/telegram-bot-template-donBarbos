# `bot/api/app.py` 注释规范

## 目标
- 保留必要信息。
- 减少重复的“功能说明 / 输入参数 / 返回值”块。
- 让模块顶部和函数 docstring 更短、更像代码文档，而不是说明书。

## 采用原则
1. **模块顶部**只写三部分：
   - 模块用途
   - 核心职责
   - 必要依赖
2. **函数 docstring**只保留一句话概括。
3. **实现细节**尽量用清晰的代码名表达，不再用长注释重复说明。
4. **只有复杂或容易误解的地方**才补充短注释。
5. **注释不堆叠**：同一段逻辑不同时写“功能说明 / 输入参数 / 返回值 / 逐行解释”。

## 当前文件示例
### 推荐
- `"""API 应用模块。"""`
- `"""创建并配置 FastAPI 应用。"""`
- `"""记录请求方法、路径、状态码、耗时和客户端 IP。"""`

### 不推荐
- 长篇模板式注释
- 重复解释函数名已经能表达的内容
- 同一函数里连续写很多段“输入参数 / 返回值”

## 适用范围
- 先只用于 `bot/api/app.py`
- 如果你满意，再把同样风格推广到其他 API 文件
