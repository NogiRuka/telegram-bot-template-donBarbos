# 现有命令功能、用户界面与优化审查

> 文档状态：当前实现核对
>
> 核对日期：2026-09-21
>
> 核对范围：`bot/handlers/`、`bot/keyboards/`、`bot/utils/permissions.py`、`bot/runtime/hooks.py`
>
> 说明：本文记录的是代码当前真实行为。标记为“建议”的内容尚未实现。

## 一、结论摘要

当前机器人已经形成两套入口：

1. Telegram 输入框旁的斜杠命令菜单；
2. `/start` 打开的图片、说明文字和内联按钮主面板。

主面板已经覆盖大部分普通用户与管理员业务，但命令发现、权限校验和菜单注册没有形成同一套数据源。代码中实际注册了 27 个主要命令入口，默认斜杠菜单却仍是模板内容；`/help` 只扫描其中一部分，因此用户看到的命令、帮助里列出的命令和实际可执行命令彼此不一致。

建议把主面板继续作为普通用户的主要入口，把斜杠菜单收敛成按聊天场景和角色展示的快捷入口，并建立统一的命令注册表，同时生成 Telegram 命令菜单、`/help` 和开发文档。

## 二、入口与权限模型

### 2.1 角色

| 角色 | 当前判定方式 | 主要入口 |
| --- | --- | --- |
| 普通用户 | `user_extend.role` 无管理员角色时默认为 `user` | `/start`、普通用户命令、用户面板 |
| 管理员 | `user_extend.role == admin` | 用户面板 + 管理员面板 + 管理命令 |
| 所有者 | `user_extend.role == owner` | 用户面板 + 管理员面板 + 所有者面板与命令 |
| 当前群管理员 | Telegram `get_chat_member()` 返回管理员或创建者 | 群组配置、导出、搜索、问答等群内操作 |

管理员与所有者身份来自数据库角色；“当前群管理员”来自 Telegram 当前聊天成员状态。两种管理员概念目前混用，导致部分命令的权限与界面文案不一致。

### 2.2 控制层

当前有三层控制：

- 角色控制：`require_owner`、`require_admin_priv`；
- 功能开关：用户功能与管理员功能，可由所有者面板或 `/feature` 切换；
- 命令开关：用户命令与管理员命令，可由所有者使用 `/command` 切换。

功能开关控制业务模块，命令开关只控制部分斜杠命令。群组目录中的命令、`/gen_gf` 和 `/test_rp` 不在命令开关注册表内。

## 三、当前斜杠命令清单

### 3.1 公共入口

| 命令 | 场景 | 权限 | 当前行为 |
| --- | --- | --- | --- |
| `/start` | 仅私聊 | 必须属于配置的主群组 | 重置旧主消息，按角色加载首页图片、文案和按钮；群聊中只提示用户私聊机器人 |

### 3.2 用户命令

| 主命令 | 别名 | 场景 | 命令开关 | 当前行为 |
| --- | --- | --- | --- | --- |
| `/help` | `/h` | 未显式限制 | 否 | 根据数据库角色展示动态帮助；只收录 `handlers/command/user`、`admin`、`owner` 中带 `COMMAND_META` 的模块 |
| `/get_file` | `/gf` | 未显式限制 | `get_file` | 按文件唯一名或 Telegram `file_unique_id` 查询并发送文件；一次可输入多个值并去重 |

红包主要格式：

```text
/rp <总额> <份数> [留言]
/rp <总额> <份数> fixed [留言]
/rp <总额> @用户名 [留言]
/rp <总额> <用户ID> exclusive [留言]
```

回复某位用户的消息后执行 `/rp <总额> [留言]`，也会创建该用户专属红包。红包有效期为 10 分钟，普通红包份数上限为 200。

## 四、用户当前看到的界面

### 4.1 Telegram 斜杠菜单

机器人启动时会删除默认命令，然后只为 `en`、`uk`、`ru` 三种语言注册以下模板菜单：

```text
/help       help
/contacts   developer contact details
/menu       main menu with earning schemes
/settings   setting information about you
/supports   support contacts
```

其中只有 `/help` 存在处理器；`/contacts`、`/menu`、`/settings`、`/supports` 都没有实现。代码里虽定义了管理员 `/ping` 和 `/stats` 菜单，但管理员菜单注册块被字符串注释，不会执行。中文等未注册语言没有可用的默认命令菜单。

`/help` 会动态扫描三类命令元数据：

## 五、已发现的问题

### 5.1 P0：权限与数据安全

#### P0-1 私聊群组配置可绕过目标群管理员校验

`GroupAdminFilter` 在私聊中直接返回 `True`。因此普通用户可发送 `/gc <群组ID或@用户名>`，代码只验证机器人能否取得目标群信息，没有验证操作者是否为目标群管理员。

建议：私聊操作目标群时，必须对目标 `chat_id` 调用 `get_chat_member(target_chat_id, user_id)`；仅目标群管理员、创建者或数据库管理员可继续。

#### P0-2 群组配置按钮缺少回调级权限校验

`group_config:*`、`save_mode:*`、清空消息确认等回调处理器没有重新检查操作者权限。管理员在群里打开配置面板后，其他群成员也可能点击按钮切换配置或清空历史消息。

建议：所有修改型回调必须重新验证当前操作者；不要把“能看到按钮”当作授权。清空消息还应要求二次确认并记录操作者。

#### P0-3 生产环境始终加载 `/test_rp`

测试命令在命令总路由中无条件注册，`DEBUG` 状态不会影响它。虽然当前要求数据库管理员权限，但它仍扩大了生产攻击面并暴露测试行为。

建议：移入测试路由并仅在 `DEBUG` 下加载，或删除该入口，保留红包向导的“预览封面”功能即可。

### 5.2 P0：明确的功能错误

#### P0-4 `/enable_group` 和 `/group_info` 使用了不存在的模型字段

- 新建群组配置时传入 `is_enabled`、`save_mode`，模型真实字段是 `is_message_save_enabled`、`message_save_mode`；
- `/group_info` 读取 `save_text`、`save_media`、`save_forwarded`、`save_replies`、`total_users`，这些字段不存在。

这两条命令在相应分支会发生运行时错误。并且 `/enable_group` 对已有但模式为 `DISABLED` 的配置只修改布尔值，实际保存逻辑仍会判定为未启用。

建议：统一调用已有的群组配置 service，不在命令处理器中直接拼模型字段。

#### P0-5 导出时间范围按钮没有生效

点击“最近 7 天 / 最近 30 天 / 全部消息”时，代码只更新提示文案，没有保存选择。随后点击任意导出格式都会固定导出最近 30 天、最多 5000 条。

建议：把时间范围放入 callback data 或 FSM 状态，例如 `export:csv:7d:<chat_id>`，服务端重新校验范围和权限。

### 5.3 P1：用户看见的入口与实际功能不一致

#### P1-1 默认斜杠菜单基本不可用

当前菜单来自原始模板，四个入口没有处理器，且没有中文菜单。用户最先看到的入口会直接失败。

#### P1-2 `/help` 展示错误命令

群组管理元数据写的是 `name = "group"`，所以帮助显示 `/group (/g)`；真实处理器却是 `/groups (/g)`，不存在 `/group`。

此外，帮助中的用法和错误提示仍写 `/admin_enable_group`、`/admin_disable_group`、`/admin_group_info`，这些命令也不存在。

#### P1-3 图形界面提示错误命令

管理员面板中的“群组管理”和“统计数据”目前只是占位弹窗，分别提示使用 `/admin_groups`、`/admin_stats`；真实命令是 `/groups`、`/stats`。

#### P1-4 群组配置的“返回主面板”是死按钮

群组配置保存模式界面使用 callback `home:back`，代码中没有对应处理器。通用首页回调实际是 `back:home`。

#### P1-5 命令来源不统一

- Telegram 菜单来自 `keyboards/default_commands.py` 的硬编码字典；
- `/help` 来自 `COMMAND_META` 动态扫描；
- 路由本身来自装饰器；
- 群组命令、`/gen_gf`、测试命令又在其他目录独立注册。

因此新增、改名或下线命令时，很容易只改到其中一处。

### 5.4 P1：权限语义与展示不一致

- `/save_enable`、`/save_disable` 的文档把它们称为群组管理员命令，代码实际要求数据库管理员；
- `/message_stats` 没有当前群管理员校验，任何群成员都可查看统计；
- `/stats`、`/groups`、`/group_info`、`/sr` 可在群聊执行，可能公开管理数据或审批信息；
- `/quiz`、`/quizs` 使用“管理员命令开关”，但执行者只需是当前群管理员，不要求数据库管理员；
- `private_chat_only` 在错误场景直接静默返回，用户不知道为什么没有响应。

建议先明确“数据库管理员”和“当前群管理员”的能力边界，再统一装饰器、帮助文案和 Telegram 菜单作用域。

### 5.5 P1：Markdown 与错误信息可靠性

多个处理器把用户输入、群名、投稿标题、管理员留言或异常文本直接放入 Markdown/MarkdownV2 回复，特殊字符可能导致整条消息发送失败。部分异常内容还会直接展示给用户。

建议：动态值统一转义；普通结果尽量使用 `parse_mode=None`；面向用户显示稳定的中文错误编号，详细异常只写日志。

### 5.6 P2：体验与维护性

- `/save_emby` 只有开始和成功状态，异常时可能留下“正在同步”；
- `/quizs` 部分成功时不汇总失败数量与原因；
- `/get_file` 多文件发送没有“第几项/共几项”进度，也没有最终汇总；
- `/ban`、`/disable_user` 等高风险命令直接执行，缺少确认步骤；
- 动态模块加载捕获所有异常后只 `print` 或静默忽略，启动看似成功但命令可能缺失；
- `COMMAND_META` 使用无结构字典，无法在启动时校验命令名、别名、聊天场景、权限和示例。

## 六、建议的用户命令 UI

### 6.1 设计原则

1. 主面板负责“按任务找功能”，斜杠菜单负责“快速直达”；
2. 菜单只展示主命令，不把所有别名重复展示；
3. 私聊、普通群成员、群管理员、数据库管理员和所有者使用不同菜单作用域；
4. `/help` 根据当前聊天场景与身份过滤，不显示在当前位置无法执行的命令；
5. 每个命令详情统一展示用途、权限、可用场景、格式、示例和风险提示。

### 6.2 建议的普通用户主面板

把高频任务直接放在首页，并为命令帮助与红包增加可见入口：


## 七、建议的实现结构

### 7.1 统一命令注册表

为每个命令声明结构化元数据：

```python
class CommandSpec(TypedDict):
    name: str
    aliases: tuple[str, ...]
    description: str
    role: Literal["user", "admin", "owner", "group_admin"]
    chats: tuple[Literal["private", "group"], ...]
    feature_key: str | None
    command_scope: Literal["user", "admin"] | None
    menu_visible: bool
    usage: tuple[str, ...]
    examples: tuple[str, ...]
    destructive: bool
```

同一份注册表用于：

- 生成 Telegram `BotCommand` 菜单；
- 生成 `/help` 与内联命令中心；
- 生成本文命令表；
- 启动时检查重复命令、别名冲突、缺失描述和无效作用域；
- 为所有者命令开关提供可选项。

### 7.2 路由加载

推荐显式注册生产命令路由。若继续使用 `pkgutil` 动态扫描，至少应：

- 记录模块名和完整异常；
- 启动失败时终止，而不是静默缺少命令；
- 忽略 `_` 开头的内部模块；
- 在启动日志中打印已加载命令数量与名称；
- 禁止测试目录在非 `DEBUG` 环境注册。

### 7.3 权限校验

建议定义清晰的可复用策略：

```text
private_user
database_admin_private
owner_private
current_chat_admin
database_admin_or_current_chat_admin
```

命令处理器和回调处理器必须使用同一策略。所有修改、删除、审批、封禁、开关操作都要在点击回调时重新鉴权。

## 八、推荐改造顺序

### 第一批：立即修复

1. 修复 `/gc` 私聊目标群权限和所有群组配置回调权限；
2. 下线生产 `/test_rp`；
3. 修复 `/enable_group`、`/group_info` 字段错误；
4. 修复导出时间范围；
5. 把默认斜杠菜单替换为真实命令，至少先提供中文默认菜单；
6. 修复 `/help`、管理员占位弹窗和群组配置返回按钮中的错误命令或 callback。

### 第二批：统一体验

1. 建立结构化命令注册表；
2. 按聊天作用域与角色注册 Telegram 菜单；
3. 实现内联命令中心；
4. 把求片/投稿、红包助手和帮助提升到用户首页；
5. 在所有者面板补充命令开关 UI。

### 第三批：可靠性优化

1. 为高风险命令增加确认与审计记录；
2. 统一 Markdown 转义和错误输出；
3. 为同步、批量问答、多文件发送补充进度与汇总；
4. 为命令注册表、权限策略和菜单生成增加自动化检查。

## 九、需要确认的产品选择

在改代码前建议先确认以下决策：

1. 普通用户是否以主面板为主，只在斜杠菜单保留 4 个高频入口；
2. 群组消息统计是否允许所有群成员查看，还是只允许群管理员；
3. `/save_enable`、`/save_disable` 是允许当前群管理员使用，还是只允许数据库管理员；
4. `/stats`、`/groups`、`/sr` 是否强制仅私聊执行；
5. 管理员面板中的群组管理和统计，是直接实现图形页面，还是暂时跳转到正确命令说明；
6. 是否保留 `/quizs` 名称兼容，同时新增更直观的 `/quiz_batch`；
7. 所有者的命令开关是否需要在 UI 中展示，还是继续只保留 `/c`。

确认这些边界后，建议先完成第一批修复，再做命令中心和首页布局调整。
