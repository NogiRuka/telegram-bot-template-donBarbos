## 二、已删除的 `/unban`

删除范围：

- `/unban <用户ID>` 和别名 `/ub`；
- `/ban` 结果消息中的“解除封禁”按钮；
- `unban:*` 回调处理器；
- `unban_user_service()` 专用服务逻辑；
- 命令清单和项目结构文档中的 `/unban` 展示。

数据库中既有审计记录不会删除；通用的 `USER_UNBLOCK` 审计类型仍被 Emby 启用功能使用，因此不属于 `/unban` 的残留。

## 三、`/ban` 审查结果

### 3.1 当前真实语义

`/ban <Telegram用户ID>` 只能由数据库管理员或所有者在私聊中执行。它会：

1. 封禁配置项 `settings.GROUP` 指向的主群成员；
2. 删除该用户关联的 Emby 账号；
3. 软删除数据库中的 Emby 用户和关联设备；
4. 写入审计记录并发送管理员通知。

因此它是符合当前需求的“系统级用户清退”，不是普通群聊管理命令。群内广告治理应使用 `/spam`。

### 3.2 本轮修复

- 禁止操作者封禁自己；
- 禁止封禁机器人自身；
- 禁止封禁数据库角色为 `admin` 或 `owner` 的用户；
- 禁止封禁主群的管理员或群主；
- 删除已经失效且有误导性的解除封禁按钮。

### 3.3 确认保留的设计

- `/ban` 封禁 Telegram 用户时必须连带删除关联 Emby 账号和设备数据；
- 不拆分群封禁与 Emby 删除，也不更改当前命令名称；
- 后续若允许普通用户执行 `/ban`，复用通用命令授权表的 `global` 作用域，但需要单独设计高风险操作的授权入口和确认流程。

## 四、`/spam` 第一版设计

### 4.1 执行操作

推荐操作：管理员或获授权成员回复广告消息并发送：

```text
/spam
# 或短别名
/s
```

也支持：

```text
/s 123456789
/s @username
```

执行顺序：

1. 校验操作者是当前群管理员或当前群已授权成员；
2. 拒绝对操作者本人、机器人、群管理员和群主执行；
3. 先封禁目标账号；
4. 封禁成功后，删除被回复的广告消息；
5. 查询消息保存表，最多批量清理该用户在当前群最近 100 条可定位消息；批量失败时降级为逐条删除；
6. 标记成功删除的数据库消息记录并写入审计日志；
7. 返回实际删除成功数和尝试数。

封禁成功后，触发命令和成功消息都会在 5 秒后自动删除；一般失败和用法提示会保留，便于排查。权限不足提示按下文规则自动删除。

机器人执行 `/spam` 封禁前会登记真实发起人。Telegram 随后产生群成员封禁事件时，原有 Emby 清理和通知链会使用真实发起人的 ID 与姓名，通知显示“由某某使用 /spam 标记为垃圾账号并封禁”，而不是“被机器人踢出”。同一次操作仍只发送一条封禁通知。

### 4.2 权限管理

只有目标群管理员可以管理授权。权限管理命令可在群组或机器人私聊中执行；私聊时管理 `settings.GROUP` 配置的主群，并校验操作者是否为该群管理员：

```text
/s g 123456789
/s g @username
/s r 123456789
/s l
```

管理员也可以回复目标成员的消息：

```text
/s g
/s r
```

兼容参数：

- 授权：`g`、`grant`、`allow`、`add`、`授权`；
- 撤权：`r`、`revoke`、`deny`、`remove`、`撤权`；
- 列表：`l`、`list`、`列表`。

兼容动作与用户名连写，例如 `/s g@username`；也会容错 Telegram 文本中出现的 `/s g\@username`。任何无法识别的参数都会停止处理并提示用法，不会降级为垃圾账号封禁。显式提供目标时只使用该目标，只有未提供目标时才读取被回复用户。

授权按“用户 + 命令名称 + 作用域”保存。作用域支持系统全局 `global` 和指定群组 `group:<chat_id>`。当前 `/s g` 只授予所在群的 `spam` 命令权限；未来可用全局作用域承载 `ban` 等系统级命令。获授权成员只能执行 `/spam`，不能查看、授予或撤销权限。授权和撤权命令只要格式正确并完成处理，无论权限状态是否发生变化，触发命令和结果消息都会在 5 秒后自动删除。

私聊只开放 `g/r/l` 权限管理操作；实际封禁和消息清理仍必须在目标群中执行。权限不足时统一提示“你没有权限执行此操作”，不暴露详细判定规则；权限不足提示和触发命令都会在 5 秒后自动删除。

授权列表复用通知群组的用户链接格式，显示 Telegram 用户姓名并链接到 `tg://user?id=...`；点击姓名即可打开对应用户资料，不在正文中直接展示数字 ID。生成列表时优先读取当前群成员的最新姓名，失败时回退到数据库资料。

执行 `/s l`、`/spam l` 或对应长参数查看授权列表时，无论列表是否为空，列表回复和触发命令都会在 5 秒后自动删除。

### 4.3 平台限制

Telegram Bot API 不能按用户检索群内全部历史消息，因此“删除他发过的消息”的准确边界是：

- 被回复的目标消息会直接尝试删除；
- 其余消息必须已被本机器人保存到 `messages` 表；
- 单次最多处理最近 100 条，避免长时间占用处理器和触发限流；
- 已超出 Telegram 可删除范围、已被删除或机器人无删除权限的消息会失败；
- 返回值使用“成功数/尝试数”，不会把尝试删除误报为成功。

`@用户名` 只能从机器人已经记录的 `users` 表解析。用户从未与机器人产生过可记录交互、没有用户名或改过用户名时，应改用回复操作或数字 ID。

## 七、`/h` 权限化帮助

`/h` 现在只展示当前用户实际拥有权限的命令：

- `/help 获取帮助` 固定显示在第一行；
- 当前群管理员额外看到 `/s`、`/q`、`/qs`；私聊时按配置的主群判断身份；
- 获得当前群 `/spam` 授权的成员额外看到 `/s`；私聊时按主群授权判断；
- `/q`、`/qs` 仍只能在群内执行，`/s` 的清理操作也仍只能在群内执行；
- 机器人管理员看到机器人管理命令，但不会仅因机器人管理员身份而看到群管理员命令；
- 机器人所有者在以上基础上看到所有者命令；
- `/help` 不检查命令开关或功能开关；是否可用由用户实际调用命令时统一判断。

帮助列表不显示“基础命令”“群组管理”等分类标题，只保留“完整命令名 空格 一句话说明”。详细参数由执行命令时的针对性提示负责展示。

命令元数据统一以 `COMMAND_META["name"]` 保存完整命令名，以 `alias` 保存短别名。已修正 `/groups` 和 `/submission_review` 的旧元数据；读取命令开关时会兼容旧键 `group`、`sr`。

## 八、机器人管理员管理命令

所有者面板不再提供“管理员管理”按钮及子面板。机器人管理员统一通过所有者命令管理：

```text
/admin g <用户ID|@用户名>
/admin r <用户ID|@用户名>
/admin l
```

短别名为 `/a`，也可以回复目标用户的消息发送 `/admin g` 或 `/admin r`。`g/r/l` 分别表示授予、撤销和列表；同时兼容 `grant/add/添加`、`revoke/remove/移除`、`list/列表`。

命令只允许机器人所有者执行。管理员角色继续保存在 `user_extend.role`，不新增权限表；操作结果和管理员列表使用可点击的 Telegram 姓名链接。旧面板回调、按钮、键盘和专用列表处理器已经删除。

## 九、参数型命令的使用说明

`/help` 只负责显示简洁命令列表。不能仅靠命令本身直接执行的参数型命令，在缺少必要参数或回复目标时，必须返回该命令的详细使用方法。

当前已统一：

- `/spam`、`/admin`：展示用途、全部操作格式、回复用户的方式和示例；
- `/get_file`：展示单个或多个文件目标的格式和示例；
- `/enable_group`、`/disable_group`、`/group_info`：展示群组配置命令族的完整格式；
- `/ban`、`/disable_user`、`/enable_user`、`/quizs`、`/submission_review`：继续使用已有的统一用法生成；
- `/redpacket`：无参数时继续展示完整红包教程；
- `/command`、`/feature`、`/groups`：无参数本身是有效的查询操作，因此直接返回当前状态或列表。
